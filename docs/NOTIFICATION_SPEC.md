# LifeHub 通知仕様

## 1. 目的

LifeHub の通知は、予定の性質に応じて以下の2系統に分ける。

1. 朝・夜のまとめ通知
2. 予定単体の通知

日時が決まっている予定と、「今週中」「今月中」のような期間中にやりたい予定では通知の意味が異なるため、同じロジックへ無理に統一しない。

---

## 2. 朝・夜のまとめ通知

朝・夜のまとめ通知では、その時点で「今日やること」として意識すべき内容をまとめて通知する。

対象には以下を含める。

- 今日の固定日時予定
- 今日の終日予定
- 今日を含む複数日予定
- 現在の期間内にある「今週中」の項目
- 現在の期間内にある「今月中」の項目
- 必要に応じて、期限が近い期間予定

「今週中」「今月中」は固定日付の予定ではないが、期間内に未対応のものは朝・夜のまとめ通知へ毎回含める。

例:

```text
今日の予定
- 10:00 歯医者
- 今週中: クリーニングを取りに行く
- 今月中: 美容院に行く
```

期間予定は毎朝・毎晩の通知対象になり得るが、同一タイミングで重複して複数通知へ分割しない。

### 2.1 既定時刻

HouseToDo と同じ思想を採用し、朝・夜のまとめ通知時刻は設定画面から変更できるようにする。

初期値:

- 朝通知: 09:00
- 夜通知: 21:00

ユーザーが変更した時刻はアプリ設定として保存する。

朝・夜はそれぞれ個別に時刻を設定できるようにする。

---

## 3. 期間予定の期限

### 今週中

その週の最終日を deadlineDate として扱う。

週の開始曜日・終了曜日はアプリ設定の weekStartsOn に従う。

### 今月中

その月の最終日を deadlineDate として扱う。

### 日付範囲指定

指定した endDate を deadlineDate として扱う。

ただし初期版では日付範囲指定 + 繰り返しはサポートしない。

---

## 4. 単体通知

ユーザーが予定ごとに設定する通知は、予定の基準日時から offset を引いて発火する。

### 4.1 固定日時予定

開始日時を基準とする。

例:

```text
予定: 9/20 15:00 歯医者
通知: 30分前
```

→ 9/20 14:30 に通知。

### 4.2 終日予定

終日予定は固定時間を持たないため、単体通知の基準時刻を 09:00 とする。

例:

```text
予定: 9/20 終日 健康診断
通知: 1日前
```

→ 9/19 09:00 に通知。

```text
予定: 9/20 終日 健康診断
通知: 30分前
```

→ 9/20 08:30 に通知。

この 09:00 は終日予定の単体通知専用の既定基準時刻とする。

朝のまとめ通知時刻を設定画面で変更しても、終日予定の単体通知基準時刻は連動させない。
初期版では 09:00 固定とする。

### 4.3 今週中 / 今月中 / 期間予定

期限日の「締め切り時刻」を基準として通知する。

例:

```text
今週中
締め切り: 日曜 21:00
通知: 10分前
```

→ 日曜 20:50 に通知。

```text
今月中
締め切り: 月末 21:00
通知: 1時間前
```

→ 月末 20:00 に通知。

期間予定の単体通知は、開始日や期間途中ではなく deadline を基準にする。

---

## 5. 締め切り時刻

「今週中」「今月中」の単体通知を成立させるため、期間予定には deadlineTime が必要。

ただし毎回入力させるとフォームが重くなるため、以下の方針とする。

- 通常は既定の締め切り時刻を使う
- 必要な場合だけ変更できる
- UIでは通常非表示または通知詳細内に置く

既定の締め切り時刻は 21:00 とする。

```text
既定の締め切り時刻: 21:00
```

HouseToDo の deadlineTime の考え方は参考にできるが、LifeHub の Event モデルとして再設計する。

---

## 6. 通知 offset

1予定に複数の offset を持てる。

例:

- 10分前
- 30分前
- 1時間前
- 1日前

内部では分単位で保持する。

```text
10
30
60
1440
```

固定日時予定では startDateTime から逆算する。

終日予定では対象日 09:00 から逆算する。

期間予定では deadlineDate + deadlineTime から逆算する。

---

## 7. 通知テンプレート

通知テンプレートは、複数 offset をまとめたプリセット。

例:

```text
標準
- 1日前
- 30分前
```

```text
大事
- 1週間前
- 1日前
- 1時間前
```

テンプレートから予定へ適用した時点で、予定自身の EventNotification として値を保持する。

後からテンプレートを変更しても既存予定を自動変更しない。

---

## 8. 繰り返し予定

固定日時の繰り返し予定では、各 occurrence の開始日時を基準として単体通知を発火する。

終日予定の繰り返しでは、各 occurrence の対象日 09:00 を基準とする。

期間予定では、各 occurrence の deadline を基準にする。

例:

```text
実施時期: 今週中
繰り返し: 毎週
通知: 10分前
```

→ 毎週、その週の deadline の10分前に単体通知。

朝・夜のまとめ通知では、その週の occurrence が未対応である間は毎回「今週中」に含める。

```text
実施時期: 今月中
繰り返し: 毎月
```

→ 毎月、その月の occurrence を朝・夜のまとめ通知へ含め、単体通知は月末 deadline を基準にする。

---

## 9. 今回だけ編集との関係

繰り返し予定の今回だけ編集で日時や期限が変更された場合、その occurrence の通知基準も override 後の値を使用する。

- この予定のみ → EventOccurrenceOverride の日時 / deadline を使用
- この予定以降 → 分割後の新しい recurrence 系列を使用
- すべて → 元の Event 定義を更新

通知済み状態は occurrence 単位で一意に管理できるようにする。

---

## 10. 朝・夜通知と単体通知の違い

| 種類 | 目的 | 期間予定の扱い |
|---|---|---|
| 朝・夜のまとめ通知 | 今日意識すべき内容をまとめて知らせる | 期間内なら毎回含める |
| 単体通知 | 指定した予定のタイミングを知らせる | deadline を基準に offset 通知 |

同じ「通知」という名前でも責務を分けて実装する。

---

## 11. 設定画面

設定画面には少なくとも以下を持つ。

```text
通知

朝のまとめ通知
09:00 >

夜のまとめ通知
21:00 >
```

初期値は朝 09:00 / 夜 21:00。

HouseToDo と同様、ユーザーが後から自由に変更できるようにする。

単体予定の通知テンプレート設定とは別項目として扱う。

---

## 12. HouseToDoからの流用方針

流用候補:

- Web Push
- Push subscription
- Service Worker
- scheduled Worker / Cron
- timezone-safe notification scheduling
- deep link
- 朝・夜まとめ通知時刻を設定から変更する考え方
- deadlineTime の考え方

新規設計:

- 1予定に複数 offset
- Event occurrence 単位の通知
- period Event の deadline 基準通知
- 終日予定の 09:00 基準通知
- 朝・夜まとめ通知への period Event 統合
- 通知テンプレート

HouseToDo の単一 notificationOffsetMinutes モデルをそのままコピーしない。
