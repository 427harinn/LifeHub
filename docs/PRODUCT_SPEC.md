# LifeHub プロダクト仕様

## 1. 目的

LifeHub は、生活の予定・お金・軽い記録をひとつの時間軸で扱う**完全個人用**のスマートフォン向けアプリです。

Todo消化を中心にするのではなく、日々の予定を中心にして、家・仕事・お金・メモを自然に振り返れることを目指します。

## 2. プロダクトの基本方針

- 完全個人用とし、ユーザー間共有・家庭メンバー共有は行わない
- **Todoではなく予定を管理する。完了 / 未完了という状態は持たない**
- 予定中心で考える
- 家と仕事は分けて管理できる
- 必要なら「すべて」でまとめて見る
- お金は厳密な会計ではなく、予定額を元にした「ズボラ家計簿」とする
- 1日のメモを持ち、結果として軽いライフログになる
- 入力回数・選択回数をできるだけ減らす
- 高度な設定は必要なときだけ表示する
- HouseToDo と同じスマートフォンファーストのUI思想を継承する
- 古い履歴は無期限にD1へ蓄積せず、端末ローカルへアーカイブできる設計にする
- 機種変更・復元のためにデータのエクスポート / インポートを正式機能として持つ

## 3. ボトムナビゲーション

5項目とする。

1. カレンダー
2. デイリー
3. ＋追加
4. お金
5. 設定

中央の「＋追加」を主要な登録導線にする。

## 4. 管理対象

### 4.1 予定

予定は主に以下の情報を持つ。

- タイトル
- 家 / 仕事
- 日時または期間
- 終日
- 繰り返し
- 場所
- メモ
- 通知

予定には単日だけでなく、開始〜終了を持つ複数日予定も含む。

予定はTodoではないため、通常予定・期間予定ともに `complete / incomplete / skip` 等の状態を持たない。

通常予定は詳細画面から通常どおり編集・削除できる。
繰り返し予定は `今回のみ / これ以降 / すべて` の編集・削除をサポートする。

### 4.2 期間中にやりたいこと

「この期間内にやりたいが、実施する日付・時刻は決まっていない」項目を扱う。

例:

- 今週中にクリーニングを取りに行く
- 今月中に美容院へ行く
- 9/8〜9/12の間に役所へ行く

これはHouseToDoのTodoモデルをそのまま持ち込まず、LifeHubの予定モデルの一種として新規設計する。

`今週中 + 毎週`、`今月中 + 毎月` のように期間枠そのものを繰り返すことができる。
任意の日付範囲指定は初期仕様では繰り返し不可とする。

期間予定にも完了操作は持たない。期間が終了したら過去の予定としてそのまま履歴に残る。

### 4.3 お金

支出・収入を扱う。

主な用途:

- 単発支出・収入
- 定期支出・収入
- 将来の予定額
- 判明した実績額への上書き

LifeHubでは正確な家計簿入力を強制しない。
詳細は `MONEY_SPEC.md` を正とする。

### 4.4 メモ

2種類のメモを持つ。

- 予定メモ: 個別予定に紐づく
- 1日メモ: その日全体に紐づく「今日のメモ」

「日記」という重い位置付けにはしない。
すべて個人データとして扱う。

## 5. 家 / 仕事

予定にはカテゴリとして以下を持つ。

- 家
- 仕事

これはHouseToDoの担当者概念やHousehold概念とは別物。

- `家`: 私生活・家庭側の予定
- `仕事`: 仕事側の予定

どちらも同一ユーザー自身のデータであり、共有範囲の違いはない。

## 6. 追加フロー

中央の＋を押すと最初に以下だけを選ぶ。

- 家
- 仕事
- お金

その後は直接それぞれの登録フォームへ進む。
不要な中間選択画面は増やさない。

## 7. 予定登録UI

家・仕事は同一構造のフォームを使う。

### 上部

`以前の項目から選ぶ >`

HouseToDoと同じ考え方を採用し、過去に登録した予定を再利用できるようにする。

### 基本項目

- タイトル
- 日時設定 / 期間中にやりたい
- 終日
- 開始
- 終了
- 繰り返し
- 場所
- メモ
- 通知

### Progressive Disclosure

必要な設定だけ表示する。

- 終日なら時間入力を表示しない
- 繰り返しなしなら繰り返し詳細を表示しない
- 期間中にやりたい場合は固定時間UIを表示しない
- 無効な `period × recurrence` 組み合わせはエラー表示より選択肢を絞る
- 場所・メモなどはコンパクトな追加行として閉じておいてよい

## 8. 繰り返し

HouseToDoの繰り返し実装を参考にするが、そのTaskモデルはそのまま流用しない。

LifeHubでは「繰り返し」を純粋な recurrence として扱う。

例:

- なし
- 毎日
- 毎週
- 毎月
- カスタム

また、繰り返す期間を別に持てるようにする。

例:

- ずっと
- 指定日まで
- 開始日〜終了日

EventとMoneyの両方で利用できる共通RecurrenceRuleとして設計する。

繰り返し予定は以下をサポートする。

- 今回だけ編集 / 削除
- この予定以降を編集 / 削除
- すべての予定を編集 / 削除

詳細は `RECURRENCE_AND_OCCURRENCE.md` を正とする。

## 9. 通知

予定は複数通知に対応する。

例:

- 1日前
- 30分前

朝・夜のまとめ通知と予定単体通知は別責務で扱う。
詳細は `NOTIFICATION_SPEC.md` を正とする。

HouseToDoのPush / Service Worker / Scheduler基盤は流用候補とする。

## 10. ズボラ家計簿

### 基本思想

予定額を登録し、今月の着地をざっくり把握する。
分かったものだけ実績に置き換える。

例:

- 電気代予定: 10,000円
- 実際の請求: 5,000円
- 今月は5,000円を使用
- 翌月の予定は再び10,000円

### 月末処理

実績未入力の予定額を0円にしない。

- 実績あり → actual
- 実績なし → plannedを「みなし実績」として扱う

内部的には actual と estimated_actual を区別できるようにする。
通常UIでは必要以上に強調しない。

詳細は `MONEY_SPEC.md` を正とする。

## 11. 過去登録

予定・お金ともに過去日付へ登録できる。

CalendarやDailyで過去日を表示した状態から追加した場合、その日を初期日として使用する。

また「以前の項目から選ぶ」で過去入力を再利用できるようにする。

## 12. データ保持・バックアップ

LifeHubでは長期利用で履歴が増え続けることを前提にする。

- 最近利用するデータはCloudflare D1に保持する
- 一定期間より古い履歴は端末のIndexedDBへアーカイブできる
- アーカイブ後もCalendar / Daily / Moneyの過去表示から閲覧できる
- D1から消す前にローカル保存の成功を検証する
- 機種変更やブラウザデータ消失に備え、全データをJSON形式でエクスポートできる
- エクスポートしたJSONを新端末へインポートして復元できる
- CSVは予定・お金の閲覧用補助エクスポートとして将来対応可能

詳細は `BACKUP_AND_RETENTION.md` を正とする。

## 13. 非対象

LifeHubでは以下を中心機能にしない。

- ユーザー間共有・家庭共有
- Household / HouseholdMemberによる共有管理
- HouseToDo型の家事Todo管理
- 完了 / 未完了 / skip / pass といったTask workflow
- 買い物リスト
- 担当者ベースの家事分担
- 厳密な会計・資産管理
