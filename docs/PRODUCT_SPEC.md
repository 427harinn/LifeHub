# LifeHub プロダクト仕様

## 1. 目的

LifeHubは、生活の予定・お金・軽い記録をひとつの時間軸で扱う**完全個人用**のスマートフォン向けアプリです。

Todo消化を中心にするのではなく、日々の予定を中心に、家・仕事・お金・メモを自然に振り返れることを目指します。

---

## 2. 基本方針

- 完全個人用。ユーザー間共有・家庭メンバー共有を行わない
- **Todoではなく予定を管理し、完了 / 未完了状態を持たない**
- Calendarを中心画面にする
- 家と仕事を分けて管理し、「すべて」でまとめて見られる
- お金は厳密な会計ではなく予定額中心の「ズボラ家計簿」
- 1日のメモを持ち、結果として軽いライフログになる
- タップ数・選択回数を減らす
- 高度な設定は必要なときだけ表示する
- HouseToDoと同じスマートフォンファーストUI思想を継承する
- 角丸・余白・文字はHouseToDoと同じ、色はLifeHubのオレンジ系へ変更する
- 古い履歴をD1へ無期限に蓄積しない
- JSONバックアップ / 機種変更復元を正式機能として持つ

1. カレンダー

3. ＋追加
4. お金
5. 設定

中央の＋を主要登録導線にする。

## 4. 予定

主な情報:

- タイトル
- 家 / 仕事
- scheduled / period
- 日時または期間
- 終日
- 繰り返し
- 場所
- メモ
- 通知

予定は単日・複数日・繰り返しを扱う。

通常予定は通常編集 / 削除できる。

繰り返し予定は:

- 今回だけ
- これ以降
- すべて

の編集 / 削除をサポートする。

---

## 5. period Event

「この期間内に置いておきたいが、実施日時は決まっていない」予定。

例:

- 今週中にクリーニングを取りに行く
- 今月中に美容院へ行く
- 9/8〜9/12の間に役所へ行く

種類:

- `this_week`
- `this_month`
- `custom_range`

`this_week / this_month` は `periodAnchorDate` を持ち、対象週 / 月を安定して復元する。

許可する組み合わせ:

- 今週中 + 毎週
- 今月中 + 毎月
- custom range + 繰り返しなし

period Eventにも完了操作はない。期間終了後は過去予定として残る。

---

## 6. 家 / 仕事

予定カテゴリ:

- 家
- 仕事

どちらも同一ユーザーの個人データであり、共有範囲ではない。

Calendarの主色分けは家 / 仕事ではなく、

- 単発予定
- 繰り返し予定
- period予定

を優先する。

9. 登録

の順を基本とする。

## 8. 繰り返し

TimingとRecurrenceを分離する。

DB上のfrequency:

- daily
- weekly
- monthly

繰り返しなしはruleなし。

UI上は分かりやすさのため:

- なし
- 毎日
- 毎週
- 毎月
- カスタム

を表示してよい。

ただし**カスタムは独立frequencyではない**。

2週間ごと・曜日複数選択等の詳細設定入口であり、保存時はdaily / weekly / monthly + interval / weekdays / dayOfMonthへ正規化する。

繰り返す期間は `startsOn / endsOn` で表現する。

詳細は `RECURRENCE_AND_OCCURRENCE.md`。

## 9. Calendar

LifeHubの中心画面。

- 390×844で大きく月Calendarを表示する
- 日セル最上部にMoney金額
- その下に予定
- 複数日予定はTimeTreeのような連続帯
- 表示しきれない場合は `+N`
- 最大表示件数は実装後の密度Evidenceを見て決める

Calendarタブ:

- すべて
- 家
- 仕事
- お金

1. 終日

## 11. 通知

2系統:

- 朝・夜まとめ通知
- Event単体通知

初期値:

- 朝09:00
- 夜21:00
- period deadline 21:00
- all-day単体通知基準09:00

朝・夜は設定から個別ON/OFF・時刻変更可能。

periodはその日が有効期間内なら朝夜まとめ通知へ含め、期限後は外す。

詳細は `NOTIFICATION_SPEC.md`。

---

## 12. お金

支出・収入を扱う。

用途:

- 単発支出 / 収入
- 定期支出 / 収入
- 将来予定額
- 判明した実績額

MoneyItemはplannedAmountを持ち、occurrenceごとにactualへ置き換えられる。

月末actual未入力分は、その時点の予定額を `estimated_actual` としてDBへ固定保存する。

今月画面では:

- 支出見込み
- 収入見込み
- 残りそう

を主役にする。

詳細は `MONEY_SPEC.md`。

---

## 13. メモ

2種類:

- Event.memo
- DailyNote

DailyNoteはその日全体の軽いメモ。「日記」という重い位置付けにしない。

---

## 14. 過去登録 / 検索

Event / Moneyは過去日付へ登録可能。

Calendar / Dailyから追加した場合、その日をcontextとして引き継ぐ。

Event検索対象:

- title
- place
- memo

検索結果から該当月 / 日付へジャンプできる。

---

## 15. データ保持 / バックアップ

- D1: 直近1年 + 将来生成に必要な定義
- IndexedDB: 1年より古い履歴
- 月1回程度、12か月超履歴を安全にアーカイブ
- D1削除前にIndexedDB保存・checksum確認
- JSONはCalendar / Daily / Moneyを完全復元できる情報を含む

機種変更:

1. 完全JSON生成
2. 保存
3. 再読込・validation・checksum確認
4. 最終確認
5. D1整理
6. migration_locked
7. 新端末import
8. 復元確認
9. unlock

詳細は `BACKUP_AND_RETENTION.md`。

---
