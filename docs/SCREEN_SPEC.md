# LifeHub 画面仕様

## 1. 共通方針

- スマートフォンファースト
- `docs/DESIGN.md` を最上位のデザイン仕様とする
- HouseToDoのUIデザイン・余白・BottomSheet・フォーム行・Bottom Navigationを基本設計として継承する
- タップ数と選択回数を減らす
- 高度な設定は必要なときだけ表示する
- 月表示 → 日付詳細 → デイリー → 予定詳細の順で情報量を増やす
- 予定アプリとして扱い、完了ボタン・チェックボックス・未完了状態は表示しない
- Calendarをアプリの中心画面とし、一般的なコンパクト月表示より大きく、多くの予定情報を見せる
- iPhoneのDynamic Island / notch / status barを考慮し、画面最上部の主要コンテンツを詰めすぎない。safe-areaを確保した上で、見た目上は現在のM2 shellより少し低い位置から主要見出しを開始する
- 未実装機能のshellでも `準備中` だけを並べず、最終UIを判断できる現実的なfixture / dummy dataを表示する。dummyであることは開発用データとして内部で管理し、通常UIへ「準備中」を大量表示しない
- 前Milestoneでレビュー・merge済みのCalendar / Daily等の画面は、新機能のためにレイアウト・情報階層・interaction grammarを再設計しない。維持できない理由がある場合は、理由を報告して確認を得てから変更する

## 2. カレンダー

アプリのメイン画面。
390×844を基準に、**月表示そのものへ画面の大部分を割り当てる**。

Calendarでは、日付選択後の情報を月表示の下へ常設しない。
日付を押した後の詳細はHouseToDoと同様にBottomSheetで下から重ねて表示するため、月表示の下に文章領域を確保する必要はない。

### ヘッダー

Calendar上部はコンパクトにしつつ、以下を配置する。

1. 画面タイトル `カレンダー`
2. 右側に検索アイコン
3. 表示切替タブ
4. 月移動ヘッダー
   - 前月
   - `2026年9月`
   - 翌月
5. 月表示の直下、年月の真下中央に `今日` 導線

`今日` を画面タイトル右上には置かない。
HouseToDoのCalendarと同じ考え方で、**日付/月表示の下側に置く**。

月表示は矢印ボタンに加えて、月グリッド上の横スワイプでも切り替える。横方向56px以上かつ縦移動より大きい場合だけ月を変更し、縦方向の操作と日セルのタップは月変更に変換しない。

検索は画面タイトル右側のアイコンから開く。
検索画面/検索UI自体の本実装はSearch milestoneで行うが、それ以前のshellでもアイコン位置と遷移先placeholderは確認できるようにする。

### タブ

Calendar上部に常時表示する。

- すべて
- 家
- 仕事
- お金

月表示を圧迫しない高さで、HouseToDoのタブ/選択UIと同系統の静かな表現にする。

### 月表示の高さ

LifeHubではCalendarが主画面のため、HouseToDoよりも月セル内の情報密度を高く取る。

- 6週 / 42セルを基本とする
- 画面下部のBottom Navigation直上近くまでCalendarに使ってよい
- 選択日の説明文を下へ常設しない
- 各週行を現在のM2 shellより縦に大きくする
- 予定名・金額・件数バッジを複数行入れられる余地を持つ

Calendarは固定の最大表示件数を持たない。実際のセル高から、日付数字・罫線・safe-area・browser UIの影響を除いた`availableRows`を算出する。端末ごとに表示可能row数が変動してよく、PC screenshotより実機での崩れ防止を優先する。

390×844のmax 2 / max 3 / max 4 Evidenceは、固定maxを決めるためではなく、adaptive方式へ移行した判断の履歴として保持する。

### 日セルの情報順

日セル内は上から以下の順を基本とする。

1. 日付数字（左上固定）
   - 件数バッジは右上、日付数字と同じ高さに置く。absolute配置で予定領域を圧迫しない
2. multi-day帯とsingle-day Event
3. Money表示（summaryまたはMoney明細。表示可能なら最終row）
4. 表示しきれない場合の日付右上小型丸バッジ

Calendarは情報量を優先する。
バッジがないセルにバッジ用の固定行・固定高さを確保しない。バッジがあるセルとないセルで表示できる予定数が変わってよく、空いた高さは予定表示へ使う。
Money summaryが存在する日は、`availableRows`の最終rowをMoney専用rowとして予約する。Eventは残りrowへ表示し、Eventが少なくてもMoneyを上へ詰めない。超過Eventのみhidden countへ加える。Money summary自体はhidden countへ含めない。

Money summaryがない日は全rowをEvent表示へ使う。家 / 仕事タブではMoneyを存在しないものとして扱い、Money用row予約もMoney由来hidden countも出さない。

日セルの描画順は、背景 / 罫線、日付 / hidden件数バッジ、複数日帯 / 単日予定 / Moneyの順とする。複数日帯とsingle-day Eventは同じrowを取り合わず、Money summaryがある場合は最終rowを予約する。複数日帯はセル罫線で分断されて見えないようにする。

### すべて

日セルには以下を表示する。

- 家の予定
- 仕事の予定
- Money summaryがある場合は、その日の収支合計1行

お金の個別明細はここでは出さない。
Money summaryは予定が少なくても`availableRows`の最終rowに固定する。支出は赤、収入は青系で表示する。

### 家

家カテゴリの予定のみ表示する。

### 仕事

仕事カテゴリの予定のみ表示する。

### お金

通常Eventは表示せず、その日のMoney名称を表示する。最終rowには日計を固定する。Money明細が少ない場合も日計を上へ詰めない。

例:

- 夜ごはん
- 歯医者
- -3,000

表示可能rowを超えたMoney明細だけを件数バッジへ送る。日計はhidden countへ含めない。

### 予定の色分け

家 / 仕事をカテゴリ色で区別する。

- 家 = オレンジ
- 仕事 = 青
- 単日予定 = 背景なしの文字色
- 複数日予定 = カテゴリ色の連続帯
- period予定 = 背景帯なし。開始日の期限系文字表現

家 / 仕事の補助文字は常設しない。LifeHub全体のオレンジ系デザインシステムと調和させ、派手すぎる原色は避ける。

### 複数日予定

複数日にまたがる通常予定は、TimeTreeのように同一予定を横方向へつないだ帯として表示する。

- 予定名を毎日セルごとに繰り返さない
- 同一週内ではできる限り1本の連続した帯にする
- 週境界では次の週行へ継続する
- 帯の開始・途中・終了が視覚的につながって見えるようにする
- セル罫線より帯を上のlayerへ描画し、開始端 / 終了端だけ少しセル内側へ短くして角丸にする
- 中間部分は連続感を優先し、single-day Eventと同じrowを取り合わない
- 別予定の帯はレーン間と帯同士に隙間を置く
- 家の帯はオレンジ、仕事の帯は青とする
- 日セルごとの独立カードにはしない

### 今週中 / 今月中 / 期間予定

期間中にやりたい予定はCalendar上で帯にしない。

`今週中` はその週の開始日、`今月中` はその月の開始日にだけ表示する。
Daily / Date Sheetでは、選択日が期間内であれば従来通り確認できる。

期間予定に完了チェックは表示しない。
対象期間を過ぎたら過去の予定としてその位置にそのまま残る。

M6のperiod Eventもこの表示仕様を使う。Calendarは帯にせず、`this_week`は対象週開始日、`this_month`は対象月初、`custom_range`は`periodStartDate`にだけ表示する。Daily / Date Sheetは同じprojection結果から対象期間内の日に表示する。カテゴリ色はscheduledと同じ家=オレンジ、仕事=青で、period専用色は持たない。

### 予定が多い日

availableRowsを超えた予定、または`お金`タブで表示しきれないMoney明細は無理に詰め込まず、日付セル右上の小型丸バッジに件数数字を表示する。
例: 丸バッジ内に `3`。セル本文へ件数文字列を置かない。

`すべて`のMoney summary、`家` / `仕事`のMoney非表示分はhidden countに含めない。

タップするとその日の日付詳細で全件確認できる。

### 日付タップ

日付を押すと**HouseToDoと同系統の大きなBottomSheet**で簡易日付詳細を開く。

月表示の下へ選択日の文章を常設しない。
BottomSheetはCalendarの上へ重なるため、Calendar本体の高さを削らない。

表示内容:

- 日付は上部に1回だけ表示
- 時系列の予定一覧
- その日を含む期間予定
- `すべて` では個別Money明細を並べず、その日の収支合計だけ
- 「1日の詳細を見る」導線
- その日を初期値にした追加導線

家の予定はオレンジ、仕事の予定は青の文字色で表示し、`家` / `仕事` の補助文字は表示しない。
予定メモ全文などはここでは表示しない。

Date Sheetのinteraction:

- 左swipeで翌日、右swipeで前日へ移動する
- 予定tapは別画面へ遷移せずinline展開し、再tapでcloseする
- inline detailは日付 / 期間、場所、メモの値だけを表示する。通常行に時刻があるため時間は重複表示しない
- 行の横swipeでは編集actionを表示しない。編集はinline detail内の「編集」から行う
- `+`は大きなBottomSheetを重ねず、家 / 仕事 / お金の小型ポップアップメニューを表示する。メニューを閉じても親Date Sheetは維持する
- Date Sheetは背景tap、close操作、上から下へのdragでcloseする

### 検索

Calendar画面タイトル右側に検索アイコンを置く。

検索結果は一覧表示し、選択すると:

1. 該当月へ移動
2. 該当日を選択
3. 日付詳細BottomSheetを開く

検索対象:

- タイトル
- 場所
- メモ

ローカルアーカイブ済みデータも検索対象に含められる設計にする。

## 3. デイリー

1日単位の詳細を見る画面。
HouseToDo Homeの縦スクロール構造を参考にする。

### 日付操作

- 前日
- 翌日
- 今日へ戻る
- 左swipe → 翌日
- 右swipe → 前日

Calendarから選択した日付を引き継ぐ。

Daily headerには現在の日付を表示し、前日・翌日・今日の操作で実データを再取得する。CalendarのDate Sheetから`1日の詳細を見る`へ進んだ場合も、選択日をそのまま表示する。

### タブ

- すべて
- 家
- 仕事
- お金

### すべて

上から以下の順に表示する。

1. 予定タイムライン
2. 今日のお金
3. 今日のメモ

M4の画面順は、終日予定 → 期間予定（placeholderを含む） → 時間あり予定 → 今日のお金（収支合計） → 今日のメモとする。

#### 予定タイムライン

縦方向のタイムライン表示を基本とする。

タイムライン内の順序:

1. 終日予定
2. 今週中 / 今月中 / 任意期間の期間予定
3. 時間あり予定を時刻順

終日予定と期間予定はタイムライン上部へ積み、固定時刻を持つ予定はその下を時刻順に表示する。

時間あり予定と終日予定は同じ「予定タイムライン」というまとまりに含める。
期間予定も上部セクションとして同じ予定領域に含める。

M3/M4前のshellでも「予定はありません」だけにせず、終日・期間・時間ありの仮データを使って最終レイアウトをレビューできる状態を作る。

### 家 / 仕事

該当カテゴリの予定だけを同じタイムライン構造で表示する。
時刻または予定名をカテゴリ色にし、補助カテゴリラベルは表示しない。

### 予定行の操作

M2で確定したDailyの情報階層・spacing・dividerを維持する。M3のscheduled Eventは実データへ差し替えるが、通常行を別の詳細ページへ遷移させない。

- 行タップでその行だけを縦に展開し、存在する日時、期間、場所、メモの値だけを静かに表示する。`日付 / 時間`、`場所`、`メモ`等の項目名ラベルは表示しない。展開内の編集ボタンから編集フォームへ進む
- 再タップで閉じ、別の行を開くと前の行を閉じる
- 行の横swipeでは編集actionを表示しない。編集はinline detail内の「編集」から編集フォームへ進む
- 通常行に削除操作を露出せず、削除は展開後の深い導線または編集画面から行う
- 通常Eventとperiod予定は同じtap → inline expand → 再tap closeのgrammarを使い、編集はinline detail内の編集ボタンから行う。M4のperiod予定はinteraction確認用fixtureであり、本データモデル / API実装は後続Milestoneで行う

### お金

`すべて` タブでは`今日のお金`に今日の収支合計を表示する。個別Money明細は表示しない。
`お金` タブではMoney個別明細を表示し、最後に今日の収支合計を表示する。家 / 仕事タブではお金一覧を表示しない。

例:

- 夜ごはん
- 歯医者
- -3,000

M4のMoney表示はfixture / placeholderを含むUI確認範囲であり、予定額・実績額を扱うMoneyモデル / APIは後続Milestoneで実装する。

### 今日のメモ

お金の下に配置する。
1日単位の軽いメモ。
「日記」という名称は使わず、書かなくても違和感がないUIにする。

M4ではDailyNoteの本文を初期表示し、本文タップで同じ場所に静かな編集欄を開く。保存後は同じDaily日付へ戻る。空保存はDailyNote削除として扱う。大きなカードやモーダルは追加しない。

## 5. 家・仕事の登録画面

詳細は `EVENT_FORM_SPEC.md` を正とする。

M3では、中央`+`の家 / 仕事からscheduled Event formへ進む。Calendar Date SheetまたはDailyから追加した場合は、選択日を初期日とし、登録後は同じ画面・日付へ戻る。Calendar Date SheetとDailyの実Eventはinline展開とswipe revealから編集へ進み、専用詳細ページへは遷移しない。

フォームのカテゴリは入口で固定し、上部に家（オレンジ）または仕事（青）の小さなマーカーと短いカテゴリ表示だけを置く。繰り返しrowは`なし >`を初期表示し、BottomSheetで`なし / 毎日 / 毎週 / 毎月 / カスタム`を選ぶ。カスタムは必要なfrequency、interval、weekdays、dayOfMonth、endsOnだけを段階的に表示する。数値と単位は`[2] 週間ごと`のように一続きで見せ、form rowには人間向けsummaryを表示する。weeklyは開始日の曜日を初期選択し、終了は`なし / 日付`で見せる。場所・メモは未入力時にcompact rowで隠す。

M5ではrecurrence周辺だけをUIレビュー対象とし、M4のフォーム全体・Calendar・DailyのDOM / CSS / interaction grammarは再設計しない。繰り返し予定の編集・削除時だけscope BottomSheetを表示し、単発予定では表示しない。

通常予定は詳細画面から編集・削除できる。
繰り返し予定は `今回のみ / これ以降 / すべて` を選択して編集・削除する。scope sheetでは各rowに短い補助文を付け、`今回のみ=選択した1回だけ`、`これ以降=選択した回から先`、`すべて=系列全体（過去も含む）`とする。長い説明文は常設しない。

## 7. お金画面

上部タブ:

- 今月
- 月ごと

### 今月

上部に大きく:

- 支出見込み
- 収入見込み
- 残りそう

その下に:

- 今月のお金一覧
- カテゴリ別の支出（当月effective amountのdonut）

M9では共通MoneyProjectionのeffective amountを表示する。予定は空丸、actual / estimated_actualはチェック丸で状態を控えめに示し、内部語は通常画面に出さない。Money rowのtapはinline detailを開き、編集と実績登録・変更へ進む。行の横swipeでは編集actionを表示しない。繰り返しMoneyの編集・削除ではEventと同じBottomSheetで`この項目のみ / この項目以降 / すべての項目`を選ぶ。新規登録時のみ、登録内容として実績 / 予定を選択できる。カテゴリ別の支出donutはeffective amountを使うM9 UI polishの先行範囲であり、M10の月別・長期・比較グラフは未着手とする。

M8前のshellでも `記録はありません` だけで終わらせず、最終UIを判断できる仮の金額・カテゴリ・明細を表示する。

### 月ごと

- 月別推移グラフ
- 月単位の支出 / 収入

月を選択すると詳細へ進める。

過去月は実績 + みなし実績で集計する。
今月は予定額を含む着地見込みとして扱う。

## 8. 設定

HouseToDoの設定/その他画面構造をベースにする。

**Settings rootには各設定値を直接並べない。**
トップ画面は「設定カテゴリへ入るための一覧」とする。

初期のroot項目:

- アカウント >
- 通知 >
- カレンダー >
- お金 >
- データ / バックアップ >
- その他 > （必要になった場合）

各rowはHouseToDoと同じようなシンプルなlist rowで、タップすると個別設定画面へ遷移する。
トップ画面に `タイムゾーン Asia/Tokyo` や `週の開始 月曜日` 等を直接大量表示しない。
必要ならrow右側に短いsummaryを1つだけ表示してよい。

### アカウント

個別画面で扱う候補:

- メール
- ログアウト
- 将来の機種変更状態

### 通知

個別画面で扱う:

- この端末の通知（subscription状態、初期OFF。許可済みsubscription後ON）
- 朝のまとめ通知 ON/OFF
- 朝のまとめ通知時刻（初期09:00）
- 夜のまとめ通知 ON/OFF
- 夜のまとめ通知時刻（初期21:00）
- 期間予定の期限時刻（初期21:00）
- 通知テンプレート

permission dialogはページロード直後に開かず、「この端末の通知」のユーザー操作からだけ要求する。朝夜設定と端末subscriptionは別状態として保持する。

### カレンダー

個別画面で扱う:

- 週の開始曜日
- timezone等Calendar表示に関係する設定

### お金

個別画面で扱う:

- お金カテゴリ
- Money表示に関する将来設定

### データ / バックアップ

個別画面で扱う:

- 機種変更 / バックアップ
- バックアップを書き出す
- バックアップを読み込む
- ローカルアーカイブ状態
- 必要に応じて手動アーカイブ

共有設定は持たない。

M2時点で未実装の設定も、`準備中` だけを並べず、**root → detail の画面構造がレビューできるfixtureを作る**。
実際のwrite APIが未実装の場合は保存を行わなくてもよいが、最終的なrow構成・section hierarchy・navigationを判断できる状態にする。

## 9. データアーカイブ表示

古いデータがD1から端末IndexedDBへ移動済みでも、通常のCalendar / Daily / Money画面から可能な限り同じように閲覧できるようにする。

ユーザーに「これはDB」「これはローカル」と毎回意識させない。

ただし設定画面では以下を確認できるようにする。

- クラウド保持期間（初期1年）
- ローカルアーカイブ件数 / 対象期間
- 最終エクスポート日時
- 機種変更状態

端末データを消すとローカルアーカイブも失われる可能性があるため、バックアップ未作成時にはその旨を分かりやすく表示する。

## 10. 画面間の戻り動作

HouseToDoで実装した `returnTo` の考え方を継承候補とする。

例:

- Calendarの9/10から追加 → 登録後9/10のCalendarへ戻る
- Dailyの過去日から追加 → 登録後同じ日のDailyへ戻る

戻る操作でも元の画面・選択日をできる限り維持する。
